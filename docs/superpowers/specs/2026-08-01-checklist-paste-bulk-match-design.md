# 체크리스트 붙여넣기 일괄 매칭 설계

- 날짜: 2026-08-01
- 상태: 승인됨 (구현 계획 단계로 진행)

## 배경

QA 라운드 화면의 `ChecklistPanel`(`src/components/app/qa-rounds-panel.tsx`)은 이번 세션에서 검증할
이벤트·사용자 속성을 검색해서 고르는 UI를 제공한다. 지금은 한 줄짜리 검색창에 이름을 하나씩 입력하고
엔터를 눌러야 하나씩 담긴다 — 검증 대상 이름 목록을 외부(스프레드시트, 슬랙 메시지 등)에서 이미
가지고 있는 경우에도 하나하나 타이핑해야 하는 번거로움이 있다.

이 문서는 검색창에 여러 이름을 한 번에 붙여넣으면(줄바꿈 또는 쉼표로 구분) 일치하는 이벤트·사용자
속성을 한꺼번에 담아주는 기능의 설계를 다룬다.

## 목표

- 검색창에 줄바꿈 또는 쉼표로 구분된 여러 이름을 붙여넣으면, 일치하는 이벤트·사용자 속성이 한 번에
  담긴다(체크리스트에 바로 저장되는 게 아니라, 기존 "담기(staged)" 상태로 들어가서 "이렇게만 검증"을
  눌러야 실제 저장된다 — 기존 흐름과 동일).
- 붙여넣은 이름 하나가 이벤트와 사용자 속성 양쪽에 동시에(우연히 같은 이름으로) 존재하면 둘 다
  담는다.
- 결과를 토스트로 요약한다: 새로 담긴 개수 / 이미 체크리스트·담긴 목록에 있어서 건너뛴 개수 / 일치하는
  이름이 없는 개수(이름 일부 포함).
- 이름 하나만 붙여넣는 기존 사용 방식(검색창에 커서 두고 하나씩 타이핑 후 엔터)은 전혀 바뀌지 않는다.

## 비범위 (Out of scope)

- 이벤트 프로퍼티(개별 이벤트 속성)나 커스텀 어트리뷰트의 하위 필드는 매칭 대상에 포함하지 않는다 —
  지금 검색창이 원래 이벤트·사용자 속성만 대상으로 하는 것과 동일하다.
- 부분 일치(포함) 매칭은 지원하지 않는다 — 붙여넣기는 완전 일치(대소문자 무시)만 지원한다. 기존
  단일 검색창의 실시간 부분 일치 필터링은 그대로 유지되고, 이번 기능과는 별개다.
- `qa_round_checklist_items` 테이블 스키마, `useAddChecklistItems`/`useRemoveChecklistItem` 등
  커밋 단계의 로직은 건드리지 않는다 — 붙여넣기는 오직 "무엇을 `staged`에 넣을지" 계산에만 관여한다.

## 매칭 기준

- 붙여넣은 텍스트를 줄바꿈(`\n`) 또는 쉼표(`,`) 기준으로 나눈다 (정규식 `/[\n,]+/`).
- 각 조각을 trim하고, 빈 문자열은 버린다. 남은 토큰 중 중복된 문자열(대소문자 무시)은 하나로 합친다.
- 각 토큰에 대해, 프로젝트의 전체 이벤트·사용자 속성 후보군(현재 검색어와 무관하게 전체) 중
  `technical_name`이 대소문자 무시 완전 일치하는 항목을 찾는다.
- 한 토큰이 이벤트와 사용자 속성 양쪽에서 동시에 일치하면 **둘 다** 결과에 포함한다.
- 토큰이 어디에도 일치하지 않으면 "못 찾음" 목록에 넣는다.
- 일치했지만 이미 이 세션의 체크리스트에 있거나(`existingKeys`) 이미 `staged`에 담겨 있으면(같은
  붙여넣기 안에서 중복 토큰으로 두 번 걸린 경우 포함) "이미 있음"으로 센다 — `staged`에 다시 추가하지
  않는다.

## UI/트리거 설계

기존 검색창(`<Input>`, `qa-rounds-panel.tsx` 약 447행)의 모양과 위치는 그대로 두고, `onPaste`
핸들러만 추가한다:

1. 붙여넣기 이벤트에서 `e.clipboardData.getData("text")`로 원본 텍스트를 읽는다 (줄바꿈이 보존된
   상태로 읽힌다 — 이 방식을 쓰는 이유는 아래 "기술적 고려사항" 참고).
2. 위 매칭 기준으로 토큰화했을 때 토큰이 **2개 이상**이면 일괄 붙여넣기로 판단하고
   `e.preventDefault()`로 브라우저의 기본 붙여넣기 동작(입력창에 텍스트가 그대로 들어가는 것)을
   막은 뒤, 매칭 로직을 실행한다.
3. 토큰이 1개 이하면(구분자 없이 이름 하나만 붙여넣은 경우) `preventDefault()`를 호출하지 않고 기존
   동작 그대로 입력창에 붙여넣기가 진행된다 — 단일 이름 붙여넣기는 지금과 동일하게 동작한다.
4. 일괄 매칭이 끝나면 검색창을 비우고(`setSearch("")`), 새로 담긴 항목은 기존 `staged` 배열에
   추가해 기존 칩 목록 UI로 그대로 보여준다.
5. 토스트 메시지 형식: `"{담김}개 담았어요 · {이미있음}개는 이미 있어요 · {못찾음}개는 못 찾았어요: {못찾음 이름 최대 5개, 초과 시 "…외 N개"}"`. 세 그룹 중 0개인 항목은 문구에서 생략한다(예: 못 찾은
   게 없으면 "못 찾았어요" 부분 자체가 안 나온다).

### 기술적 고려사항: 왜 `<textarea>`가 아니라 `onPaste` 가로채기인가

HTML `<input type="text">`는 값에 줄바꿈 문자를 담을 수 없어서, 여러 줄을 그냥 붙여넣으면 브라우저가
줄바꿈을 없애버려 `\n` 기준 분리가 안 된다. `<textarea>`로 바꾸는 대안도 있었지만, 평소 이름 하나씩
타이핑해서 검색하는 주 사용 패턴에서 입력창이 커지고 여러 줄 UI가 생기는 게 오히려 방해가 된다고
판단해 채택하지 않았다. 대신 `onPaste` 이벤트의 `clipboardData`에서 직접 원본 텍스트(줄바꿈 포함)를
읽고, 여러 줄/항목으로 판단될 때만 `preventDefault()`로 기본 붙여넣기를 막는 방식을 쓴다 — 입력창
모양은 그대로 유지하면서 붙여넣기 순간에만 다른 동작이 켜진다.

## 구현 메모

- `searchTargets`(현재 검색어로 필터링된 후보 목록)가 계산하는 "이벤트+사용자 속성 전체, 이미
  담긴/체크리스트에 있는 것 제외" 목록을 `availableTargets`라는 별도 `useMemo`로 분리해서
  붙여넣기 매칭에도 재사용한다. (참고: 이 분리 자체는 이번 기능과 무관하게 이미 다른 작업에서
  시도된 적이 있어 보이는데, 그 변경은 아직 main에 커밋되지 않은 상태라 이번 구현에서 새로
  브랜치를 딸 때는 반영되어 있지 않다 — 이번 계획은 처음부터 직접 분리한다.)
- 새 유틸 함수 `parsePasteTokens(text: string): string[]` — split → trim → 빈 값 제거 → 대소문자
  무시 중복 제거.
- `onPaste` 핸들러 내부에서 `events`/`customAttributes` 전체를 `technical_name` 소문자로 매핑한
  조회 구조(`Map<string, SearchTarget[]>`, 하나의 이름에 이벤트+속성 둘 다 걸릴 수 있으니 배열)를
  만들어 각 토큰을 조회한다.
- 붙여넣기 한 번 안에서 같은 대상이 여러 토큰(중복 이름)으로 다시 걸리는 것을 막기 위해, 이번
  붙여넣기 배치 안에서 새로 추가한 키를 추적하는 로컬 `Set`을 둔다.

## 테스트 관점

이 프로젝트는 자동화 테스트가 없으므로 `agent-browser`로 수동 검증한다:

- 존재하는 이벤트 이름 여러 개를 줄바꿈으로 구분해 붙여넣기 → 모두 `staged`에 담기는지, 토스트에
  담긴 개수가 맞는지
- 쉼표로 구분해 붙여넣기 → 동일하게 동작하는지
- 이미 체크리스트에 있는 이름을 섞어서 붙여넣기 → "이미 있음" 개수로 집계되고 중복으로 안 담기는지
- 존재하지 않는 이름을 섞어서 붙여넣기 → "못 찾음" 목록에 이름이 표시되는지
- 이름 하나만(구분자 없이) 붙여넣기 → 기존과 동일하게 입력창에 그대로 들어가는지 (동작 안 바뀜)
- `npx tsc --noEmit`, `npm run build` 클린 확인
